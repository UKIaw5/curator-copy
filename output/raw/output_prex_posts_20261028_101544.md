**Executive Summary: REVA**

REVA (Real-time Vulnerability Analysis) is a novel AI-driven vulnerability detection framework designed to bridge the performance gap between slow, high-accuracy agentic detectors and fast, low-accuracy static analysis tools. By leveraging the internal representations of Large Language Models (LLMs) rather than relying on generated text outputs, REVA achieves state-of-the-art accuracy with a fraction of the computational cost and latency, enabling real-time security screening for code generated by AI agents.

**What is REVA?**
*   **Core Function:** A real-time vulnerability detector that screens individual software functions for security flaws immediately upon creation.
*   **Problem Addressed:** Current agentic security tools (like VulTriage) are highly accurate but too slow (taking minutes per function) for real-time use due to the multi-step reasoning process required. Conversely, simple LLM prompting or fine-tuned models are faster but significantly less accurate because they lack deep contextual understanding.
*   **Key Innovation:** REVA compresses the complex "reasoning" phase of agentic detectors into a single forward pass of an LLM by projecting that context into the model’s hidden states.

**How It Works: Technical Architecture**
REVA operates by feeding a composite context into an LLM and then using a trained probe to interpret the model's internal representation of that context. The workflow consists of three distinct layers:

1.  **Contextual Input Assembly:**
    For each new function, REVA constructs a rich prompt that includes:
    *   **Pre-computed Threat Model:** A high-level understanding of the specific module containing the function.
    *   **Lightweight Static Analysis Findings:** Immediate structural code checks.
    *   **Call-Graph Information:** Data regarding how the function interacts with the broader codebase.
    *   *Note:* This assembly mimics the evidence-gathering phase of a human security expert or an agentic system, but does so statically and pre-computed.

2.  **Internal Representation Extraction:**
    *   Instead of asking the LLM to *generate* a verdict (e.g., "Vulnerable" or "Safe"), REVA processes the function and context through the LLM (specifically tested on GLM-5.3-Flash).
    *   It captures the **hidden state** (internal vector representation) of the LLM after processing this context. These hidden states contain the semantic and logical connections the model has formed about the code's security posture.

3.  **Probe-Based Classification:**
    *   A lightweight, trained **probe** (linear classifier) is applied to these internal representations.
    *   The probe decodes the "security reasoning" embedded in the LLM’s latent space to output a vulnerability prediction.
    *   *Key Insight:* This method exploits the fact that LLMs internally encode complex code understanding during processing, even if their final text generation is unreliable or hallucinated.

**Why It Matters: Performance and Metrics**
REVA delivers a critical trade-off improvement, offering near-agentic accuracy at the speed of standard inference.

*   **Speed & Latency:**
    *   **~1 second per function:** On PrimeVul’s held-out test set, REVA achieves real-time screening.
    *   **250x Faster:** Compared to the state-of-the-art agentic detector VulTriage.
    *   **Cost Efficiency:** Less than 1/10th the cost of agentic detectors.

*   **Accuracy Benchmarks (PrimeVul Held-out Test Set):**
    *   **REVA (on GLM-5.3-Flash):** 60.0% accuracy.
    *   **VulTriage (Agentic, same LLM):** 59.2% accuracy.
    *   **Direct LLM Prompting:** REVA’s probe is **14%–17% more accurate** than asking the same LLM to generate a direct verdict, proving that internal representations are a more reliable signal than generated text.

*   **Cross-Model Generalizability:**
    *   REVA was tested across three different open-source LLMs.
    *   It matched or exceeded VulTriage’s accuracy on all three.
    *   It was **~10% more accurate** than VulTriage on two of the three models, suggesting the probe architecture is robust and not strictly tied to a single LLM’s optimization.

**Key Takeaways for Developers and Security Teams**
*   **Real-Time CI/CD Integration:** Unlike agentic tools that must run as post-hoc batch jobs, REVA can be integrated directly into IDEs or CI/CD pipelines to flag vulnerabilities as code is written.
*   **Reduced Technical Debt:** By detecting vulnerabilities at the moment of creation, the cost of remediation is minimized.
*   **Trust in Internal State:** This research validates that LLMs possess a deep, internal understanding of code semantics that is often more accurate than their explicit, text-based outputs. Security tools can therefore bypass the noisy "text generation" step and read the model’s "thoughts" directly.

**Technical Summary: ParetoRSI-Gym**

**Overview**
ParetoRSI-Gym is a novel evaluation framework designed to assess the capabilities of AI agents in executing the full loop of Recursive Self-Improvement (RSI). Unlike traditional benchmarks that measure an agent’s ability to optimize a single metric on a static dataset, this framework simulates real-world machine learning engineering workflows. It requires an agent to autonomously search for data, curate it, train a Language Model (LLM), and evaluate the results across multiple conflicting domains. The core objective is to measure whether an AI agent can navigate the "Pareto frontier" of improvements—maximizing gains in specific domains without causing significant regressions in others.

**How It Works**
The framework operates through a constrained, multi-round agentic workflow where all variables except the data selection strategy are held constant.

*   **Fixed Experimental Constraints:**
    *   **Base Models:** Three distinct base LLMs are used as starting points (including Ministral-3-3B).
    *   **Pipeline:** A standard Supervised Fine-Tuning (SFT) pipeline is used consistently across all runs.
    *   **Toolset:** The agent is provided a fixed set of tools for data retrieval and training execution.
    *   **Domains:** The evaluation covers five specific verticals: Math, Code, Finance, Medicine, and Science.
*   **Agentic Workflow:**
    1.  **Search & Curation:** The agent identifies and selects relevant training data from external sources.
    2.  **Training:** The agent initiates the SFT process on the fixed pipeline using the curated data.
    3.  **Evaluation & Feedback:** The system evaluates the resulting model on both "proxy" benchmarks (the scores the agent might see during optimization) and independent "generalization" benchmarks.
    4.  **Iteration:** The agent reads the per-domain performance results, identifies weak areas or regressions, and repeats the cycle. The study conducts this over five rounds with multiple random seeds to ensure statistical robustness.
*   **Decoupling Overfitting from Capability:**
    *   A critical architectural feature is the separation between the benchmarks used for the agent’s immediate feedback loop (proxy scores) and the final evaluation benchmarks (generalization scores). This prevents the agent from simply "overfitting" to the specific metrics it is optimizing for, providing a true measure of capability improvement.

**Key Metrics and Results**
The study evaluates three different agent systems against the three base models. The primary finding highlights the interplay between the agent’s reasoning capability (the "harness") and the underlying LLM.

*   **Top Performer:** The combination of **Claude Code** (as the agentic harness) driving the **Opus-5** model yielded the strongest results.
*   **Aggregate Improvement:**
    *   **Relative Gain:** +9.2% improvement in generalization scores compared to the starting model.
    *   **Absolute Gain:** +2.3 points on average, weighted equally across three base models and five domains.
*   **Domain-Specific Peaks:**
    *   The highest single-domain relative gain was **+63%** in the **Medicine** domain, achieved when improving **Ministral-3-3B**.
    *   This demonstrates the agent’s ability to identify and exploit specific data niches that drastically improve underperforming verticals.
*   **Strategic Divergence:**
    *   Analysis revealed that different agent systems developed unique data selection strategies. Even when using the same base model, different agents prioritized different types of data, suggesting that the "harness" (the agent’s reasoning loop and tool usage) is as critical to RSI performance as the raw model intelligence.

**Why It Matters to Developers and AI Researchers**
1.  **Moving Beyond Single-Metric Optimization:** Traditional LLM tuning often focuses on one benchmark (e.g., MMLU). ParetoRSI-Gym forces the development of agents that understand trade-offs. A developer building an enterprise LLM cannot afford a 50% gain in code generation if it breaks financial compliance or medical reasoning. This framework provides a metric for "holistic" model improvement.
2.  **Validation of Agentic RSI Loops:** This is a step toward validating AI systems that can perform end-to-end ML engineering tasks (data sourcing -> training -> eval). It shifts the focus from "Can the model write code?" to "Can the agent manage the entire MLOps lifecycle successfully?"
3.  **Harness-Model Synergy:** The finding that the "harness matters as much as the model" suggests that developers should not view RSI as purely a base-model limitation. Investing in robust agentic orchestration layers (like Claude Code) can yield disproportionate returns even with smaller base models (e.g., Ministral-3-3B).
4.  **Robustness against Overfitting:** By using separated generalization benchmarks, the framework provides a more honest assessment of real-world utility, protecting developers from deploying models that look excellent on training-time metrics but fail in production due to domain-specific overfitting.

**Conclusion**
ParetoRSI-Gym establishes a rigorous baseline for evaluating AI agents in complex, multi-domain post-training scenarios. It demonstrates that current state-of-the-art agentic systems (like Claude Code/Opus-5) can drive meaningful, multi-domain improvements (+9.2% avg) without relying on simple distillation, provided they navigate the data-selection trade-offs effectively.

**2. Core Architecture and Methodology**
The system operates through a two-stage pipeline combining data collection, policy learning, and low-level control:

*   **Data Collection (Robot-Free Demonstrations):**

    *   **Sensors:** Employs two force-sensing handheld grippers to capture hand motion and contact wrenches (force and torque data).
    *   **Body Tracking:** Uses wearable motion trackers to capture full-body kinematics, ensuring the data reflects coordinated whole-body movements.

*   **Policy Network: Force-Reactive Diffusion Policy:**
    *   **Architecture:** A diffusion model designed to generate stochastic, multi-modal action distributions.
    *   **Inputs:** Fuses three modalities:
        1.  Visual observations (vision).
        2.  Proprietary sensor data (proprioception).
        3.  Measured external wrenches (force/torque feedback).
    *   **Outputs:** Predicts whole-body actions and specific **per-hand force commands**. This allows the robot to adjust its internal state based on real-time interaction forces, rather than relying solely on pre-computed trajectories.

*   **Control Layer: Hybrid Compliance Whole-Body Controller:**
    *   **Function:** Executes the policy’s commands while maintaining dynamic balance.
    *   **Mechanism:** Implements a **hybrid compliance** strategy. It uses the integral of force error measured by real physical Force/Torque (F/T) sensors to drive the actuators.
    *   **Compliance Logic:** The controller allows each hand to track commanded force accurately along the specified direction while remaining compliant in orthogonal directions. This prevents destructive force accumulation during contact while ensuring the desired manipulation effect.

*   **Success Rate Comparison:**

    *   **Baseline (Position-Only Policy):** Achieved only a **26.7% success rate** when trained on the same demonstrations and executed by the same controller.

    *   In simulated environments, the controller successfully tracked per-hand force commands of varying magnitudes and directions.
    *   Crucially, this force tracking was achieved with **little loss in whole-body motion accuracy**, indicating that the hybrid compliance approach does not sacrifice stability or locomotion quality for manipulation precision.
